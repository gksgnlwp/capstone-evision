# 백엔드 연결 기준

현재는 백엔드 소스나 OpenAPI를 받지 않은 상태입니다. 엔드포인트, DTO, 인증 방식, 페이지네이션 형식을 임의로 확정하지 않았습니다. `apiClient`는 연결에 필요한 공통 요청 처리까지만 구현합니다.

## 모드

- `VITE_DATA_MODE=mock`: 기능별로 등록한 예시 핸들러만 실행합니다. 미등록 기능은 명시적으로 실패합니다.
- `VITE_DATA_MODE=api`: `VITE_API_BASE_URL` 아래로 실제 요청을 전송합니다. 실패 시 예시 데이터로 바꾸지 않습니다.
- `VITE_API_TIMEOUT_MS`: 요청 제한 시간. 기본 10000ms입니다.
- `VITE_*`는 브라우저 번들에 포함됩니다. 비밀키·공공 API 인증키를 넣지 않습니다.

## 기능별 구현 방식

각 작업의 기능 폴더에서 화면 모델과 서비스 인터페이스를 정의하고, mock fixture와 실제 DTO 변환을 분리합니다. 응답을 제네릭 타입으로 지정해도 런타임 검증이 되지 않습니다. 실제 연동 시 스키마 검증 또는 명시적 파싱을 어댑터에 추가합니다.

```ts
const load = (signal: AbortSignal) => apiClient.request('백엔드에서 확정한 경로', {
  query: { page: 0 }, signal,
});
```

`path`에는 베이스 하위 경로를 주고 쿼리는 `query`에 전달합니다. 빈 값은 생략하고, 0과 false는 유지합니다. AbortSignal은 화면 이탈/재조회 시 취소에 사용합니다.

401·403·404·서버 오류·연결 오류·타임아웃·잘못된 JSON을 구분합니다. 401은 기능별 인증 컨텍스트에서 로그인으로 전환할 근거로 사용합니다. 공통 클라이언트가 임의로 라우트를 변경하거나 로그인 정보를 저장하지 않습니다.

현재 fetch는 `credentials: include`를 사용하지만 인증 방식 확정은 아닙니다. 운영자 인증은 6번 작업에서 실제 토큰/쿠키 규격, CSRF, CORS와 함께 검토합니다. 비밀번호나 토큰을 localStorage에 저장하는 코드는 없습니다. 서로 다른 도메인에 연결할 경우 백엔드 CORS와 쿠키 정책이 필요합니다.

## 백엔드 소스 확인 후 확정할 항목

1. 노선, 기관, 검색, 상세, 이력, 즐겨찾기 요약, 수집 현황 API의 URL과 실제 필드
2. 지도 bounds 형식, 방향 코드, 접근유형, 충전기 유형과 페이지네이션
3. 추천 API 입력·응답과 예측 없음/통계 대체의 의미
4. 타임스탬프 시간대, 갱신 지연 기준과 null의 의미
5. 운영자 로그인·실패 제한·세션 만료·권한과 관리 기능의 실제 지원 범위

## 요구사항 유지 규칙

- M05는 M06에서 여는 선택 화면. 기본 흐름은 M01 → M02 → M06.
- 기본 예측 시점은 30분. 15·45·60분은 서버 지원 확인 전 활성화하지 않습니다.
- 예측 없음 또는 산출 후 1시간 이상이면 0%나 한산함으로 표시하지 않습니다.
- `UNKNOWN` 충전 상태도 이용 가능으로 변환하지 않습니다.
- 현재 상태 갱신 시각과 예측 산출 시각을 구분합니다.
- 휴게소 방향 필터와 같은 노선 IC 포함 정책을 구분합니다. IC 거리 근사는 실제 길찾기가 아닙니다.
- 즐겨찾기 최대 20개와 선호 기관은 브라우저에 저장합니다.
- 선호 기관 목록의 서버 전달 여부는 분석서/설명서에 차이가 있으므로 추천 계약 확인 때 확정합니다. 기본 개인화 저장을 서버 사용자 계정으로 만들지 않습니다.
- 자동 수집·집계·예측 배치는 백엔드 책임입니다. 프론트는 상태를 표시하며 클라이언트 타이머로 수집 작업을 실행하지 않습니다.
