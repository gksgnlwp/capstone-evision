# 실제 데이터 시연 순서

1. `backend/scripts/snapshot/README.md`에 따라 **별도 로컬 DB**에 스냅샷을 적재한다. 기존 시연 DB에 넣으면 데이터가 교체된다.
2. 백엔드를 `--evision.collection.enabled=false`로 실행해 공공 API 수집을 멈춘다.
3. 프론트에서 `npm run smoke:api`로 공개 API 7종을 확인한다. 첫 추천 요청은 큰 집계 테이블을 읽으므로 화면 녹화 전에 한 번 실행해 둔다.
4. `npm run dev:api`로 실제 데이터 모드를 연다. 브라우저 위치 권한을 허용하고 노선·진행 방향·남은 주행 가능 거리를 선택한다.
5. M06에서 기본 `빈자리 우선`과 `가까운 순`을 전환하고, 같은 휴게소의 운영기관별 충전소가 묶이는 것을 보여 준다. M07에서 두 충전소를 비교한다.
6. M02·M03·M08에서 현재 충전 상태와 마지막 수집 시각을 보여 준다. 수집 지연 문구가 나오면 스냅샷 적재 시각을 확인하고 필요하면 다시 적재한다.

추천 API는 도착 시점의 **이용 가능 확률**을 제공하지만 예상 빈 충전기 **대수**는 제공하지 않는다. 화면의 현재 이용 가능 대수와 혼동해 설명하지 않는다. 현재 스냅샷에는 AI 예측 결과가 없어서 추천 근거는 과거 이용 통계 등으로 표시된다. 백엔드는 정상 급속충전기가 하나도 없는 충전소를 추천 후보에서 제외한다.

공공 API가 지연되는 시간대에도 시연할 수 있도록 이 로컬 스냅샷으로 화면을 미리 녹화해 둔다. 녹화 전에 수집 시각과 추천 결과를 다시 확인한다.
